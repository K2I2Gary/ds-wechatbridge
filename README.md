# 通到微信（dsh-wechat-bridge）

> **这是修改版**：上游是 [Yuuyuko-uu/dsh-wechat-bridge](https://github.com/Yuuyuko-uu/dsh-wechat-bridge)（作者 Yuuyuko-uu，MIT），中间经过 [thawline/dsh-wechat-bridge](https://github.com/thawline/dsh-wechat-bridge) 的实用化修改。本仓库（[K2I2Gary/ds-wechatbridge](https://github.com/K2I2Gary/ds-wechatbridge)）基于 1.3.4 继续加了 1.3.5–1.3.8 的功能，具体见文末「相对原版的改动」。

让 DSH 里的 AI 伙伴和微信双向聊天：**你在微信里发的话转进 DSH，伙伴说完一整轮，最后一句（和表情包图片）发回微信。**

**不注入、不 hook、不改微信。**
- 收消息：读微信 4.x 的本地 SQLite 数据库（只读，要求微信处于登录状态）
- 发消息：Windows UI Automation + 剪贴板，驱动微信窗口真的去打字、真的去粘贴图片

所以它用的是**你自己的微信号**，不是机器人。朋友收到的，就是你本人在说话。

## 它长什么样

```
微信 ──读本地库──> 插件里的 Python 桥接 ──POST /dsh-wechat-bridge/receive──> DSH 会话
      <──UIA 发送── 插件里的 Python 桥接 <──GET /dsh-wechat-bridge/outbox──  DSH 会话
```

宿主半边管会话绑定、权限、队列；Python 半边管读库、发送、日记。中间走本机 HTTP。

## 装

```
dsh plugin --profile desktop add github:K2I2Gary/ds-wechatbridge
```

或 设置 → 插件 → 安装，填 `github:K2I2Gary/ds-wechatbridge`。

装完**重启一次 DSH**，打开 **设置 → 通到微信**。

## 第一次用（三步）

1. **装依赖**：点「装依赖」。有现成的 Python 环境（装好 `wechatauto-replica` 的）就直接填「解释器」路径，不用建虚拟环境；没有就让它用系统 Python（3.10+）建一个。长文本 / 卡片 / 动图靠 `zstandard` 解压，发送的 OCR 兜底靠 `winsdk`，都会一起装。
2. **启动**：点「启动」，下面会滚日志，看到「桥接已就绪」就成了。
3. **选会话**：挑一间「默认会话」，打开「总开关」。先留着「试运行」看它记的「该发什么」对不对，再把试运行关掉。

之后在微信里跟**文件传输助手**说话，就等于跟伙伴说话；别人的私聊、群里的话也会转进来。

### 设置页结构（1.9.6）

设置页分成六个模块：**连接与启动 / 接收与绑定 / 人格与说话 / 群聊与记忆 / 联网搜索（独立） / 测试与日志**。常用项直接露出，解释器、令牌、人格文件、看图、本地知识库等收在「高级」折叠区；保存按钮固定在顶部。「群聊与记忆 → 清除上下文记忆」可以按聊天清除或清空全部本地记忆（RAG / 笔记 / 联网摘要）。完整线框图见 [docs/UI.md](docs/UI.md)。

## 不想装 Python？用自带的运行环境

如果本仓库的 Release 里放了打好的 Python 3.12 运行环境（Windows x64，已经装好 `wechatauto-replica`、`uiautomation`、`numpy`、`zstandard`、`winsdk`、`Pillow`、`pywin32`、`comtypes` 等），可以直接用，不需要再联网装东西。

```
解压 wechat-bridge-runtime-win64-py312.zip
把里面的 python 文件夹放到  ~/.dsh/wechat-bridge-runtime/python
（也就是 C:\Users\<你>\.dsh\wechat-bridge-runtime\python\python.exe 存在）
```

插件启动桥接时会自己找这个位置，不用填「解释器」、也不用点「装依赖」。想放别处也行，把那个 `python.exe` 的路径填进设置里的「解释器」就行。

> 这份环境是绿色版：整个文件夹搬到哪都能跑，删掉就等于卸载。装依赖时如果发现它是好的，会直接用，不会建 venv。

## 权限：只有主人能动电脑

| 谁 | 能干什么 |
| --- | --- |
| **主人**（`主人` 里填的 wxid / 昵称） | 什么都能 —— 聊天、读文件、跑命令、改设置 |
| **别人** | **只能聊天**。这一轮所有工具都会被硬拦（不是靠嘴劝，是在工具执行前直接拒掉） |

实现方式：外部消息进来时，插件给那间会话的 agent 挂一道 `tools.guard`。这一轮如果是外人叫醒的，任何工具调用都会被拒绝，只放行文字回复。这一轮结束闸就抬起来。

所以外人就算在微信里说「帮我删掉 D 盘」，工具层直接拒绝，模型只能回一句「这个我做不了」。

⚠️ 前提是宿主要提供 `tools.guard`（本版本 DSH 有）。没有的话日志会警告一句「这层宿主没有 tools.guard」，那就只剩嘴上约束了。

## 群聊

| 设置 | 作用 |
| --- | --- |
| **群上下文条数** | 被叫到时，往前读几条群聊天一起给模型看。默认 6，填 0 = 不带 |
| **群回复间隔秒** | 同一个群，两条回复之间至少隔几秒。默认 30，填 0 = 不限 |
| **群每小时上限** | 同一个群一小时最多接几次。默认 6，填 0 = 不限 |
| **群聊日记** | 群里**所有**消息（不点名的也记）按天写成 markdown |
| **不回谁（屏蔽）** | 一条一个标签，命中的会话 / 人不回复也不记日记（默认：微信运动、微信团队、微信支付、服务通知、订阅号消息、折叠的群聊） |

群里默认**只有被点名才进来**（正文里有：大肥鱼 / 鲸鲸 / 鲸鱼娘 / 鲸鱼 / 肥鱼），或者**主人说话**。点名规则写死在 `bridge/wechat_bridge.py` 的 `DEFAULT_ALIASES`，想改就改那行。

日记存在 `~/.dsh/wechat-diary/<YYYY-MM-DD>/<群名>.md`，一天一个文件，当天追加：

```markdown
# 组队叫战狗 单排叫野狗 · 2026-10-26

- 15:07 饮茶：现在有比赛？
- 15:08 Zierk：昨晚一点
```

## 微信语义与历史记忆（RAG）

### @ 不再被抹掉

微信 4.x 群文本里的 @ 有两种写法：英文/数字昵称后面跟 `U+2005` 终止符，中文昵称直接连着正文。桥接会按「群成员名最长匹配 + U+2005」解析，正文保留成 `@昵称`，再额外给模型一句：

```
（这条 @ 了：@你、@张三）
```

- `@你` 表示在叫这个登录账号（也就是你的 AI 伙伴），`@所有人` 也算点名
- 群里被点名时仍然走「必须回」；没点名时可以回 `[不回]`
- 正文里直接写别名（大肥鱼 / 鲸鲸等）也算在叫它

### 历史记忆（RAG）

收到一条消息时，桥接会在**当前会话**最近 N 天（默认 30 天）的历史里找相关的旧消息，和最近几条上下文一起交给模型：

```
（我翻了翻「周末活动群」以前的聊天（近 30 天），和这句有关的：
[10-20 21:03] 张三：上次说的那个配置我发群里了
[10-22 08:10] 你：看到了，晚上试试
）
```

- 纯本地词面检索：中文二元词 + IDF + 时间衰减 + 原句命中加成，**不建向量库、不调 embedding、不上传聊天记录**
- 只查当前会话，不跨私聊、不跨群，避免串台
- 设置页「群聊与记忆」里可以调「检索条数 / 天数」，填 0 条 = 关
- 群聊会排除掉已经作为「群上下文条数」带上的那几条，不重复

## 本地知识库（local_search）

桥接在后台建一个本地 SQLite（FTS5）库：`~/.dsh/wechat-bridge-memory.db`。

- 微信历史：只索引「只听」里的聊天；启动时回填最近「本地库天数」（默认 180 天）/ 每聊最多「本地库每聊条数」（默认 500）条；之后新消息实时写入
- 笔记：`~/.dsh/wechat-bridge-notes` 下的 `.md` / `.txt`，每 5 分钟扫一次；设置里可以改目录
- 检索：中文按二元词切，FTS5 排序；宿主提供 `local_search` 工具
- **关键词注意力**：`keyword_search` 把微信/笔记/联网结果按「关键词重叠 × 权重 + 来源权重 + 时间衰减」打分，softmax 归一化成占比，从高到低最多返回 5 条；权重来自独立搜索区块里设置的关键词（同词取最大）
- **联网入库**：`keyword_search` 的 `web=true`（或设置里开着「联网搜索」时默认）会调 Tavily / DuckDuckGo，把标题和摘要写进 `web_info` 表，之后本地搜索也能命中
- **去重**：检索结果按正文指纹（归一化前 180 字）和 URL 去重，微信/笔记优先，本地和联网重合的条目只留一条
- 工具参数：`local_search {query, chat?, limit?}`；`keyword_search {query, chat?, web?, limit?}`
- 示例：把资料放进笔记目录，跟伙伴说「搜一下本地笔记：部署步骤」「联网搜一下最近的 XX，存进本地库」

### 独立联网搜索（不需要启动桥接）

设置页「四、联网搜索（独立）」里直接输入关键词搜索，**不依赖桥接进程**：

- 默认会**抓每条结果的网页正文**（限 1.5MB / 6 秒，4 个并发），从正文提取关键词；不想抓可以关掉「抓网页关键词」
- **每次搜索存成一组**（最近 5 组）；组里有关键词、出现次数、权重和结果
- 每个关键词都可以调**权重（0–10）**；权重会参与 `keyword_search` 的注意力排序
- 组卡片里有 **Top 10 关键词权重条形图**（单系列、直接标数值，浅色/深色都适配）
- 搜索后同时保存 `.md` 和 `.json`：`~/.dsh/wechat-bridge-notes/web/<时间>-<关键词>.{md,json}`；JSON 含 `query / ts / keywords / points / results`，方便本地记忆或其它程序调取
- 同时写入 `web_info` / `search_groups` / `search_keywords` 表；下次 `local_search` / `keyword_search` 能命中
- 模型有独立的 `web_search` 工具：`{query, limit?, save?, fetch?}`
- 也可以不开 DSH，直接跑：

```powershell
python bridge/web_search.py "DeepSeek 最近发布" --limit 5
python bridge/web_search.py --list-groups --db ~/.dsh/wechat-bridge-memory.db
python bridge/web_search.py --set-weights 1 '{"deepseek": 3.5}' --db ~/.dsh/wechat-bridge-memory.db
```

- 搜索接口：Tavily（设置里填密钥）；没密钥退 DuckDuckGo HTML

## 表情包

伙伴在回复里写 `[表情: 描述]`，插件会去 `dsh-meme` 的表情库里按 caption / 关键词找那张图，**当图片消息发到微信**，那串描述本身不会出现在正文里。

找不到对应图片时保持原样（发出去的就是文字），不会丢内容。

## 「文件传输助手」

自己发给自己的消息本来会被跳过（防自问自答），但文件传输助手放行 —— 那是你留给自己的对话窗。两道防回环：

1. 自己刚发出去的几条，按文本比对跳过（比对前先规整空格换行）
2. 往外发完的 12 秒内，文件传输助手里冒出来的消息一律不读

## 只听选中的会话

设置里「只听这些会话」留空 = 全都听；填了（微信显示名 / wxid / `xxx@chatroom`）就只读这些：

- 名单外的私聊、群消息：**不转进 DSH、不下载图片、不写群日记、也不回**
- 名单内的群仍然按「点名 / 主人 / 频率」那套规矩走
- 「屏蔽」优先级更高：同一个会话既在「只听」又在「屏蔽」里，还是不理
- 设置页的「最近来找过的」会动态列出所有会话，点一下就能加进 / 移出名单。名单外的会话只上报名字 / id / 群还是私聊，**不上报任何消息内容**；同一会话 10 分钟最多报一次
- 改完保存，桥接 30 秒内生效；重启桥接时也会按它启动

## 人格画像（本地文件）

把 `humanity.txt` 放在插件目录（或 `~/.dsh/wechat-persona.txt`），桥接会读来做人格设定；设置页「人格画像」里也能填任意路径。

- 第 1 条微信消息带完整人设，之后每 N 条（默认 10）重提一次，不用每条都塞一遍
- 文件改了按 mtime 自动重读，下一条微信消息生效（不用重启）
- 注入格式是 `<system-reminder><persona>…</persona></system-reminder>`，只影响说话风格，不改变事实、工具权限和安全边界
- 关掉「启用人格」就完全不带；人设文件不存在时也不报错，只是不带

### 对话温度

设置页「人格画像」里的滑杆，0–1，步长 0.1：

| 值 | 行为 |
| --- | --- |
| 0.0 | 主动模式：主动发起话题、追问，不必等对方先开口 |
| 0.1–0.4 | 偏主动：可以接话、追问、提新话题 |
| 0.5 | 正常对话，不额外加行为提示 |
| 0.6–0.9 | 偏被动：不主动开新话题，回答简短 |
| 1.0 | 消极模式：能短则短，但绝不沉默；模型真没说话时宿主兜一句「嗯，我在。」 |

- 这个值会作为采样 `temperature`，通过 agent 作用域的 `agent/request` 注入每次模型请求；同时每条消息带一句行为提示（0.5 不加）
- 温度是**会话级**的：绑到微信的 agent 的所有模型请求都会用这个值
- 0 / 0.1 的「主动」有两层：对话内主动开话题；以及下面的「主动搭话」在空闲到点时真的发一条

### 主动搭话

温度 ≤ 0.1 时，桥接会跑一个空闲计时器：

- 超过「主动搭话分钟」（默认 30）没有新消息 → 让伙伴主动说一句，发回最近说话的微信聊天
- **自动计时器会持续触发**：主动说完后，下一次空闲到点仍会继续；每分钟设 1 就会每分钟触发一次，受「主动搭话每小时」上限约束（0 = 不限）
- **多间会话同时空闲时串行处理**：按「空闲最久优先」排队，一间先想完、回复排进队列（turn/end）之后，才轮到下一间；不会并发思考，回复分别发回各自聊天
- **不想等**：设置页「主动搭话」旁边有「现在就让她说一句」按钮，点了立即触发一次（也走同一个队列）
- 每个会话每小时最多「主动搭话每小时」次（默认 2，0 = 不限）；单个会话最多等 120 秒 turn/end，超时跳过
- DSH 重启后会从「绑定」恢复最近聊天，不用先等一条新消息；会话不活着就跳过
- 只在总开关开、桥接在跑时触发；试运行开着只记日志。手动按钮同样要求桥接在跑、会话活着

> 装到 DSH 后，把 `humanity.txt` 一起放到插件目录（`~/.dsh/profiles/desktop/node_modules/dsh-wechat-bridge/`），或者在设置页填它的绝对路径，或者放到 `~/.dsh/wechat-persona.txt`。

## 也可以直接说

不想点设置页的话，跟伙伴说一句就行 —— 插件挂了五个工具：

| 工具 | 参数 | 干什么 |
| --- | --- | --- |
| `wechat_block` | `{who, action: add / remove / list}` | 加/删/看「不回谁」名单 |
| `wechat_bind` | `{chat, session, action}` | 把某个微信聊天接到某间会话；`session` 可以只报标题（如「主要聊天记忆」），它自己去找那一间 |
| `local_search` | `{query, chat?, limit?}` | 搜本地微信历史 + 笔记 + 已入库的联网结果 |
| `keyword_search` | `{query, chat?, web?, limit?}` | 关键词注意力排序，最多 5 条；`web=true` 联网搜索并入库 |
| `web_search` | `{query, limit?, save?}` | 独立联网搜索，不需要桥接在跑；默认保存到本地并入库 |

例：「以后别理「拼多多」」「把「组队叫战狗」这个群接到主要聊天记忆那间」「搜一下本地笔记：部署步骤」「联网搜一下最近的 XX，存进本地库」。

## 边界与风险

- **图片和表情包会先“看”一眼**：收到图片 / 表情包时，桥接先把文件落盘，宿主用视觉模型写成一句中文描述再转进会话；没配视觉密钥时会标「没看清」，不会挡消息。语音、视频仍然跳过。
- **发送会抢微信窗口焦点**。正常情况不抢前台，只有发送失败重试时才把微信拉到前面。
- **同一个微信号别同时开两个桥**（比如鲸鲸的桥接），会抢窗口、发送会乱。
- 微信个人号自动化不是官方接口，**有封号风险**，建议先用小号 / 测试号。
- 微信升级可能让它失效：`wechatauto` 靠一张按版本号硬编码的地址表找控件树。升级后发不出去先看设置页下面的日志。
- **长文本 / 卡片 / 动图显示成 `[文本]`**：微信 4.x 把这些内容存成 zstd 帧，桥接环境缺 `zstandard` 时就会退化。点「装依赖」会一起装；手动补：`"<venv>\Scripts\python.exe" -m pip install zstandard`，装完重启桥接。
- **发消息报 `No module named 'winsdk'`**：`open_chat` / 发送的 OCR 兜底需要 `winsdk`。点「装依赖」会装；手动补：`"<venv>\Scripts\python.exe" -m pip install winsdk`，装完重启桥接。
- **微信窗口最小化 / 收托盘 / 被编辑器挡住后点击落到别的窗口**：桥接按「标题 + `weixin.exe` 进程」认主窗口（不再只看标题，避免把 DSH 侧栏浏览器或微信小程序窗当成微信），发送前还会用控件真实坐标校验落点；被挡住时只收掉真正挡路的那一个窗口，发完再还回去。
- **中文版 / 英文版微信**：设置页「二、启动桥接」里有「微信语言：自动 / 中文 / 英文」。默认「自动」按控件类名兼容两种语言；控件名称对不上时手动锁定，桥接 30 秒内生效，不用重启。
- 只在 Windows 上能用（UI Automation 是 Windows 独有的）。

## 相对原版的改动

原版能跑通，但真天天用就会疼。这一版补的都是那种「用着用着才炸」的地方：

- **同会话发消息不再抢前台**：微信最小化着也能发，不把窗口拉出来、不动鼠标。切会话（私聊↔群）时窗口会短暂露一下，发完自动收回。
- **输入框防残留**：以前发送失败时字会留在输入框里，下一条回车就把它带出去，同一条消息发两遍。现在发送前先清空，失败时也不再靠真实鼠标点「发送」按钮（那会让鼠标满屏乱飞）。
- **发图以数据库为准**：以前接口说成功、其实没发出去（或者反过来）。现在发完去微信库里查有没有新图片，查到才算成功，避免重复发。
- **群聊查名修正**：群的昵称查不到时用 `group_name_to_id` 兜底，否则群消息永远查不到（会导致重复发送判断失效）。
- **一轮里多条回复会拼起来发**：以前同一轮的第二句会覆盖第一句，微信只能收到最后一句。
- **临时目录兜底**：某些嵌入式 Python 探测不到可写的 `TEMP`（安全软件拦着时会这样），桥会退到自己的 `tmp/` 目录，不然连微信数据库都打不开。
- **长文本 / 动图解压**：补 `zstandard`，并在遇到 `[文本]` 占位符时回读原始行自己解压，避免长文本、卡片、动图被截成占位符。
- **发送更快**：出站轮询 0.5 秒；微信已经在前台且窗口正常时走快路径，不反复收起/还原前台窗口；拆条发送间隔 0.15 秒。
- **发送去重**：确认窗口 120 秒；超时重试前先查库，避免「其实发出去了、超时后重试又发一遍」；同一轮重复 assistant 消息和完全相同的拆条段落只发一次。
- **窗口在屏幕外/托盘时**：先 `SW_SHOW` + `SW_RESTORE` + wechatauto `ensure_visible`；仍在屏幕外就 `MoveWindow` 挪到可见位置。键盘兜底会先确认微信在前台，拿不到前台就放弃，避免把会话名粘进聊天框。
- **发送窗口兼容 / 还原**：窗口标题同时认 `微信` 和 `WeChat`；最小化或收托盘时先还原再发，发完按原状态收回，避免点击落到别的窗口。
- **`winsdk` 兜底**：补上 OCR 兜底依赖，避免 `open_chat` / 发送报 `No module named 'winsdk'`。
- **人格画像、@ 语义、历史记忆（RAG）**：见上面相应章节。

## 开发自测

改了 `lib/host.js` 或 `lib/client.js` 之后，两个脚本可以直接跑（不用开 DSH，也不碰真实配置 —— 记得把 `DSH_HOME` 指到临时目录）：

```powershell
$env:DSH_HOME="$PWD\.testhome"; node _selftest.mjs         # 假 ctx 跑一遍宿主：保存 / 绑定 / 屏蔽 / 人格 / 两个工具
$env:DSH_HOME="$PWD\.testhome"; node _selftest_client.mjs  # 假 React 把设置页渲染一遍：加标签、点绑定、轮询不冲掉
python -I _selftest_filter.py                              # 「只听」筛选纯函数
python -I _selftest_rag.py                                 # @ 解析 + RAG 检索 + zstd 解压
python -I _selftest_localdb.py                             # 本地知识库 FTS5 检索
```
